## Stored state and recovery

`remote-merge-attempts.json` and `remote-update-attempts.json` retain version-1 target/head-bound attempts. Started, failed and uncertain attempts are final for the same head; a replacement merge requires both a new head and a new captain card. Unsupported/malformed historical files are retained and refuse HTTP mutation. Existing runs without these files must obtain fresh signed current-head gates and captain intent. Legacy unbound review entries cannot carry approval. Naming/rebase requests are independently signed before their captain answer; context/params alone cannot confer authority.

Worktree records optionally contain `nativeRebase: {version:1,from,base,target}`. Each actual rebase stop saves the intermediate head. A subsequent write round validates that head and Git rebase state, preserves conflict files and defers dependency installation. Filesystem-only worker resolution is staged only inside scope; native Git continues the rebase. Further genuine conflicts get another round. Read-only review refuses an unfinished rebase. Unknown/malformed rebase records require captain recovery, with evidence retained. Imported heads advance the task's durable record under a lock/CAS; future rounds cannot restore the pre-update head. Original repository checkout/base refs are untouched.

## Vendor boundary

GitHub's synchronous merge endpoint exposes head SHA CAS, not base SHA CAS. Studio checks the current base/policy/CLEAN/non-draft state immediately before submission and verifies the authoritative merged PR afterwards. A base change after the final read relies on vendor up-to-date protection. Real mode therefore requires explicit named operation permission, a bound base proof, strict required-status protection, enforced administrators and empty user/team/app bypass allowances; absent/unreadable/unsupported protection fails closed. Queued/automatic modes and any non-200 merge acknowledgement are refused; 202/enqueued is never interpreted as merged. No real mutation is exercised or enabled by this unit's fixtures.

The separate C1 follow-up remains: optional dashboard `GitHub.start()` and native repository watchers currently own independent transports. This unit does not claim dashboard/native request coalescing. Native task waits retain their existing single-repository owner contract.

Readable Fit: new bands must not shrink Simple titles below 11px. The page canvas grows to the readable graph height (with a pixel allowance for borders); phone layouts may use one column. Detail sizing/editing remains unchanged.
