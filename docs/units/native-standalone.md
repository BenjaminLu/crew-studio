# Native Studio without firstmate v1

Why: Startup currently reads a hardcoded firstmate v1 checkout, derives its default project and protected root from that checkout, and searches v1 node_modules for a renderer. This makes dependency and readiness claims misleading on a clean machine.

What: Native startup uses Studio-owned data and a safe workspace. CREW_MAIN_PROJECT explicitly selects another project. CREW_FM_STATE remains an explicit optional legacy read adapter with its original protection boundary; no state is migrated, projected or synthesized. Native startup does not discover a legacy board secret or GitHub credential without an enabled adapter/repository. Git, provider login, the OS sandbox, Node and Python are coding/check capabilities rather than basic web requirements. Renderer tools remain optional, discovered only in managed tools, an explicit module setting, or Studio's own package. Doctor distinguishes these capabilities in English and Traditional Chinese and offers only supported install actions.

Done: tests/native-standalone.ts proves no implicit v1 state lookup, safe default project/protection scope, preserved explicit legacy fixtures, honest missing coding/interpreter dependencies, and no v1 renderer fallback (red on bc3101a). A compiled binary test starts from empty temporary HOME/data/project with PATH containing no Bun, Node, Python, Git, gh or provider CLI and serves native API/pages; no actual outside credential lookup or user configuration/service change. tests/native-standalone-ui.mjs captures readiness at 1440/390 in English/Traditional Chinese and light/dark. Independent exact-head reviews and frozen full verification remain required.

Requirements retained: Source development/build uses Bun. The distributed binary embeds Bun, web assets and native workflow/check manifests. Coding requires Git plus the chosen provider and its authenticated tool runtime, and a supported OS sandbox; built-in script checks use Node, with core/ste-wording using Python 3. Rendering requires Node, Playwright/Chromium and (for films) ffmpeg. Phone access over Tailscale and GitHub integration are optional. This unit reports these requirements; it does not port the interpreter-based check scripts or install dependencies.
