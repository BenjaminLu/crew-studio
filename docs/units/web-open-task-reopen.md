# Website access and original-task continuation

Final acceptance cards, task outputs, and both Library detail surfaces expose a version-pinned website link in a new tab. All four use one builder, `websiteHref` in `src/artifacts.ts`: `/af/<artifact>/<version>/<entry>` with the version's own entry file and every segment encoded, opened with `noopener`. `/af/` serves any page that is not one of Studio's own frames (`Sec-Fetch-Dest` other than `iframe`/`frame`, or absent) under `sandbox allow-scripts` without `allow-same-origin`. The site therefore runs with an opaque origin: its scripts run and its CSS, images, poster and MP4 load and play, but it cannot read Studio's storage (the phone token included) or cookies, open or script a Studio window, frame a Studio page (`frame-ancestors 'self'`), or call `/api`. Task reads check a bound site's bytes once per version, not on every refetch.

The Continue button appears only on the desktop, and only when the run view says the engine would make an offer (`continuable`). Its panel follows the Delete panel: a titled group, "Type R-001 to continue it", the primary disabled until the ID matches, and Keep closed as a text button on the same row. An artifact Task reads "Closed without approval" on its status pill and in its Timeline.

A closed or cancelled unfinished task can request an explicit desktop continuation offer. Confirmation requires its exact task ID. The engine verifies the signed ledger, pinned workflow, current head and context, original card, and artifact bytes and annotation records. It creates a new captain-only card on the same task while preserving original cards, outputs, history, and requirements. It does not rerun completed producers or approve a card, merge, or purchase a retry. Confirmation is idempotent across event replay and server restart.

Only a quiescent, unambiguous source-owned captain card is eligible. Agent and hook readiness holds, ambiguous cancellation, changed or corrupt evidence, and unknown card modes remain on hold. Merged or genuinely approved completed tasks cannot reopen as pending approval; new revisions require a separate flow.

Validation: `bun run test:web-open-task-reopen`. Offline tests exercise the actual engine and HTTP/UI surfaces (`tests/web-open-server.mjs` boots the real `src/server.ts`: CSRF, session and paired-phone refusals, and a probe site that tries to read storage, open a window, frame Studio and call `/api`), two engine restart boundaries, stale and corrupt evidence, phone refusal, and full multi-file website popups. They make no vendor calls or live task changes. Browser screenshots cover desktop/mobile, English/Traditional Chinese, and light/dark themes. These tests are not proof of a real paid coffee workflow completing end to end.
