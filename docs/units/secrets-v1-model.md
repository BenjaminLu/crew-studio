# Unit secrets-v1-model: rounds get their vendor token and nothing else (firstmate v1 "option A")

Why: the captain's decision (2026-10-14) 「Secret權限設計參照v1經驗」: apply firstmate v1's credential model to Studio's rounds. Borrowed from `~/Desktop/firstmate-workflow/bin/lib/fm_registry.py` (VENDORS: claude's login order, codex's login copy without its refresh token), `bin/lib/fm_sandbox_policy.py` (`keychain_read` by service and account, never a search, exit 44 = no item; `file_read` of a private file; `without_refresh`) and `bin/adapters/claude.sh` (claude's config directory is the round's own; `CLAUDE_CODE_TMPDIR`; telemetry off), generalized in `src/providers/login.ts`.

The model:
1. No keychain in rounds. Studio, outside the sandbox, reads the vendor's login and hands the round only its token. claude, in order: `CLAUDE_CODE_OAUTH_TOKEN` in Studio's environment; with API billing chosen (`CREW_CLAUDE_BILLING=api-key`, or `data/claude-billing.json`, where Studio moved the earlier keychain/API-key switch at start) `ANTHROPIC_API_KEY` or the key store's Anthropic key; the crew's own long-lived token (`claude setup-token`) in a keychain item of Studio's own (`crew-studio-claude-token`) or `~/.config/crew-studio/claude-token` (mode 600); else the access token of the captain's own login (never its refresh token), with a warning. Handed in as `CLAUDE_CODE_OAUTH_TOKEN`; claude's config directory is in the round's throwaway home. codex: `CODEX_API_KEY`, else a copy of its login file without the refresh token in the round's `CODEX_HOME`. The round profile denies `~/Library/Keychains` like every other secret folder. Every handed value is registered with the redactor when it is read.
2. No GitHub or other credential in rounds: a sandboxed CLI round gets no key from Studio's environment (not even its provider's), only the handed login and its own tool token; git push, PRs and API calls stay in Studio.
3. Egress is proxy-only (unchanged): the vendor's API hosts and Studio's tool listener.
4. Redaction: unit redaction-rules.
5. Doctor: "Vendor token handed to rounds; keychain not reachable", with the login's source and, for the fallback, how to make a crew token. The keychain switch is gone. The Doctor's status is the same resolver as the round's login, reading no keychain secret (since secrets-redaction-r3/r4). An error at one source (a keychain prompt denied, an empty item, an expired login) moves on to the next; a round is refused only when every source fails, with why each one did (claude and codex, since secrets-migrate-r5). Each claude credential is checked for its shape before a round (sk-ant-oat<nn>-… for a token, sk-ant-api<nn>-… for an API key); a mismatch is that source failing ("crew token is not a claude setup-token result (expected sk-ant-oat01-…)"), and no character of a value is ever logged or shown. The Doctor shows a keychain item as present-but-unchecked until a round tries it, then that round's outcome per source (data/login-outcomes.json: names and errors only) (since login-status-r6). Under API billing, Studio's environment key and its kept key are two sources in order; codex keys are checked too (CODEX_API_KEY sk-…, a login file's access token a JWT) (since login-status-r7); a codex login file holding neither an access token nor an OPENAI_API_KEY is refused and nothing is copied (tested since login-status-r8).

Done when (`tests/round-sandbox.ts`; red on the base unless noted):
1. A round cannot open the login keychain (a probe from inside). — "a round cannot open the login keychain …".
2. The round's env holds exactly its vendor token (the crew token Studio read through a stand-in `security`) and its own tool token; no GitHub token, no API key from Studio's environment. — "the round's env holds exactly its vendor token …".
3. No GitHub host is reachable (its proxy refuses api.github.com; already true on the base, kept as a guard), and the GitHub token file and `~/.config/gh` are among the deny-list probes. — "no GitHub host is reachable …".
4. With no login to hand, a claude round is refused before it starts. — "with no login to hand …".
5. The Doctor shows the login's status. — "the Doctor says rounds get the vendor token …".
