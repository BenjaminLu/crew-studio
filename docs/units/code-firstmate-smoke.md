# Unit code-firstmate-smoke: v2's coding workflow, end to end, on the sandbox repository

What: the `code-firstmate` workflow (packs/firstmate, docs/code-firstmate-pipeline.md) runs on the sandbox repository from intent to a local merge, in Studio's own runtime, and is seen and edited in a graph editor. The captain's first real feature on the demo repository (driven by firstmate with the claude provider, model claude-opus-5-5, for the worker, coordinator and reviewer) runs through this.

Done when (each line names its test; each is red on the base, where none of this exists):

1. The pipeline runs a two-way change on the sandbox repository end to end with the stub provider, every node and card in order: intake → worktree → spec (its checks) → dispatch card → door (two-way) → build → a forced lint failure → the refine loop's brief (checked by brief-quality, no human card) → build round 2 → CI (2 shards), fail-first, shard budget → fresh reviewer (one of three votes of the judged verdict) → the six gates on the edge into the merge card → merge card (gates, ledger split) → local fast-forward → after-merge hooks → clean up → merged. — `tests/smoke-code.ts` (23 lines).
2. The rounds follow the worktree rules (unit worktrees): the task's worktree is `data/work/sandbox/<run>` and is gone after the merge; each build round starts at the durable head with the brief bound to the round, its head and the ledger entries it came from (a `round-start` ledger record); each round hands back by a commit as the agent with run, node and round trailers; every round's exact prompt is on disk. — `tests/smoke-code.ts` "the task's worktree was …", "each build round started at the durable head …", "each round handed back by a commit as the agent …", "every agent round left its exact prompt …".
3. On the merge card, "request changes" and "close" are hold options; the card's door comes from the door node (`door_from: door`). — "on the merge card, request changes and close are hold options …".
4. The graph editor (`#/workflows/code-firstmate`): the graph with check badges on nodes and edges; drag a node (position kept for the version); keyboard (Tab to a node, arrows move it, Enter opens it; an edge is selected the same way); disconnect an edge and see the graph stop validating; add a node from the palette; reconnect by dragging from ports and see it validate again; drop a check on a node and on an edge; a params form from the check's schema with Try on sample; save as v2 with its diff; a run's live overlay. — `tests/runtime-ui.mjs`.
5. The run, started from the Runs page on v2, reaches Merged through the UI (dispatch → merge), with live node states on its graph; the workflows, editor, runs and run pages render at 1440 and 390, light and dark, with no sideways scroll. — `tests/runtime-ui.mjs`.

Also: the claude provider is wired for agent rounds in the round sandbox (unit fix-round-sandbox-cli); a hook from the palette records a note (the runtime's one built-in action, `note`); the sandbox's shard runner uses the running bun (`process.execPath`), so it runs inside a check sandbox with no PATH lookup; a card answered while its node is still finishing the card's STE check waits for it.
