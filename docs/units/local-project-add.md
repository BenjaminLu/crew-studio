# Add an existing local project

Projects → Add local project accepts an absolute local Git repository path and an optional display name. Review project performs bounded metadata reads, resolves the actual root and current named branch, and opens a real captain-only confirmation card. Preparing and cancelling never register a project. Confirmation rechecks repository identity/head and the strict registry snapshot before a CAS write. Registration alone never starts work, changes repository files, selects staffing, grants remote operations, pushes or merges.

The new registration-only source workflow is `local-project-register`, distinct from Firstmate's work-bound registration/continuation workflow. It shares the existing protected-root, canonical Git identity, alias, disabled/revoked-authority and cleanup checks. Identical pending requests reuse their confirmation; an existing canonical repository opens its existing project. Missing roots of unrelated historical registrations are skipped consistently with project staffing; existing but unverifiable registrations remain blocking. An interrupted mutation is held for review rather than replayed.

Only an authenticated desktop POST to `/api/projects/local-registration` prepares the card. Phone and unauthenticated requests refuse before inspection. Errors use source-owned localized guidance; arbitrary exceptions and Git output remain private. Requests accept only path and optional name. The legacy `/api/projects` route and pre-existing Firstmate workflow remain compatible; this feature does not claim to redesign every historical registration entrypoint.

On macOS the path field has a Choose folder… (選擇資料夾…) button beside it. A page cannot learn a folder's absolute path, so the page asks Studio: an authenticated desktop POST to `/api/projects/pick-folder` (the same gate as `/api/projects/local-registration`: POST only, desktop only, Studio's session) runs `osascript` with `choose folder` (an argument vector, no shell; the prompt is an argument, never part of the script text; `tell me to activate` brings the dialog forward without scripting another application, so no Automation permission is asked for) and answers `{path}` with the trailing slash dropped, or `{cancelled:true}` when the captain cancels (AppleScript error -128). The chosen path fills the field and the form's state, so a redraw keeps it; the field stays editable, and Cancel changes nothing. One dialog is open at a time (a second request answers 409 `busy`); a dialog left open five minutes is closed (504 `timeout`); a page that goes away closes it. The route registers nothing and starts nothing: the path still goes through Review project. Elsewhere than macOS the route answers 501 `unsupported`, and the sidebar read (`GET /api/projects/overview`) carries `folderPicker: false`, so the page shows no button; a phone is never offered it.

After confirmation, use Projects to open the project, configure its Crew, and separately connect GitHub and dispatch a coding task. Empty folders, detached HEAD and unborn repositories are not supported. No clone, Git init, fetch, install or shell command is inferred from the supplied path.

Validation: `bun tests/local-project-add.ts` covers actual confirmation, cancel, head/registry drift, duplicates, canonical aliases, invalid paths, restricted fields and access. `bun tests/local-project-add-ui.ts` operates the real UI at desktop English/light and mobile Traditional Chinese/dark, including actual approval/cancel and screenshots. `bun tests/folder-picker.ts` covers the folder route with an injected runner (gating, cancel, trailing-slash trimming, one dialog at a time, timeout, non-macOS) and `bun tests/folder-picker-ui.mjs` the button in a browser with the route stubbed (fills the field, survives `render()`, Cancel, busy, hidden off macOS); neither opens a real dialog. Existing native registration, project overview and Projects UI tests remain required. Offline fixtures prove wiring and guards, not model performance or production repository changes.
