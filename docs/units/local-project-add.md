# Add an existing local project

Projects → Add local project accepts an absolute local Git repository path and an optional display name. Review project performs bounded metadata reads, resolves the actual root and current named branch, and opens a real captain-only confirmation card. Preparing and cancelling never register a project. Confirmation rechecks repository identity/head and the strict registry snapshot before a CAS write. Registration alone never starts work, changes repository files, selects staffing, grants remote operations, pushes or merges.

The new registration-only source workflow is `local-project-register`, distinct from Firstmate's work-bound registration/continuation workflow. It shares the existing protected-root, canonical Git identity, alias, disabled/revoked-authority and cleanup checks. Identical pending requests reuse their confirmation; an existing canonical repository opens its existing project. Missing roots of unrelated historical registrations are skipped consistently with project staffing; existing but unverifiable registrations remain blocking. An interrupted mutation is held for review rather than replayed.

Only an authenticated desktop POST to `/api/projects/local-registration` prepares the card. Phone and unauthenticated requests refuse before inspection. Errors use source-owned localized guidance; arbitrary exceptions and Git output remain private. Requests accept only path and optional name. The legacy `/api/projects` route and pre-existing Firstmate workflow remain compatible; this feature does not claim to redesign every historical registration entrypoint.

After confirmation, use Projects to open the project, configure its Crew, and separately connect GitHub and dispatch a coding task. Empty folders, detached HEAD and unborn repositories are not supported. No clone, Git init, fetch, install or shell command is inferred from the supplied path.

Validation: `bun tests/local-project-add.ts` covers actual confirmation, cancel, head/registry drift, duplicates, canonical aliases, invalid paths, restricted fields and access. `bun tests/local-project-add-ui.ts` operates the real UI at desktop English/light and mobile Traditional Chinese/dark, including actual approval/cancel and screenshots. Existing native registration, project overview and Projects UI tests remain required. Offline fixtures prove wiring and guards, not model performance or production repository changes.
