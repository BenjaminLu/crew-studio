# Remote CI, reconciliation and external waits (A4/A5/C1)

Why: publication alone cannot prove required remote checks passed or that the PR still names the reviewed head. In-memory waits lose their deadlines after restart.

What: explicitly granted GitHub projects gain read-only required-policy/check/status/PR/ref reads. Required identities include name and app id (or exact legacy status context), pinned policy hash and PR head. Missing/pending results wait until a persisted absolute deadline; skipped/neutral/cancelled are failures. A single owned watcher per exact repository/grant wakes all matching tasks idempotently. Local projects create no watcher and perform no credential discovery.

Authoritative closed/mismatched PR/ref stops with a bilingual captain card at recovery/start and before merge presentation. Authenticated API redirects are manual; download origins receive no authorization and no signed URL is retained. All existing local coding/GitHub regressions stay green.

## R2 closed-list remediation

1. Run abort and ownership bind publication REST/owned Git, initial reconciliation/policy, gate reads, merge presentation and stop-card checks. State/card/ledger writes recheck ownership after awaits. External presentations are tracked; cancelling a raising card releases its owner. Ordinary late check results are refused; deliberate lifecycle on_cancel checks retain their existing reporting contract. Held real REST responses test cancel/delete in publication, reconcile, policy, gate and merge phases.
2. Version-1 descriptors validate the complete recorded PR identity (id/repository/base/branch prefix/ref/head/URL), policy member types/identity/hash and absolute dates before subscription. Malformed records, including a cached successful completion, stop immediately with the original evidence retained and no HTTP/watcher.
3. Each subscriber has its own owned absolute-deadline timer. A short deadline joining a busy long request expires before that response is released; the long task keeps the sole request owner. Unsubscribe clears subscriber/request/poll timers and aborts the last request.
4. Completed external hooks run their attached checks in the canonical parallel, nonblocking report contract. A version-1 externalCompletion record stores result/visit before checks; externalHookReport stores visit and signed per-check sequence ids. Recovery reuses completed signed checks without action replay. If only the report marker reached disk before its context event, recovery rebuilds context without duplicating notes or checks. Actual cancellation runs no attached checks. Ordinary returned failure reports checks like the previous hook contract; a waiting/refused action remains incomplete.

Upgrade: these completion/report fields are additive; old v1 waiting descriptors without them register normally with the original deadline and visit. Unsupported/malformed waiting descriptors retain evidence and stop. No v1 state adapter, model/config override or remote write is added.

SWEPT: all await phases of remote publication/read/presentation; wait registration/cached completion/stop; per-subscriber deadline while busy; hook start/completion/replay/check reporting and raising-card cancellation. Four standing items are addressed as classes, including ordinary card/check late-write guards and the marker-before-context crash boundary.
