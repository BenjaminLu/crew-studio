# Reviewer modes: diff and run, like v1

Captain: 「reviewer可以diff模式review跟v1一樣, 唯讀不開放網路是安全的」, and 「不一定只讀文字檔」. Borrowed from v1: config.yaml `reviewer: mode: diff|run`, bin/fm-review.sh, skills/reviewer/SKILL.md. This unit absorbs review-depth-card and the reviewer-depth r1 findings (#1 unsatisfiable reads, #2 unsatisfiable execution).

Done when (`tests/review-depth.ts`; red on 15562f8 and on 4a9e349):
1. Policy `reviewer.mode` (project, workflow or org; firstmate pack default diff). Diff mode: no execution; a shallow verdict is refused naming the files to read; a reading reviewer passes review-depth with nothing executed; the merge card says "Reviewed in diff mode". — "diff mode: …" lines, "the merge card says 'Reviewed in diff mode'".
2. Run mode: run_tests and run_command (a throwaway copy, sandbox, no network, no credentials); review-depth needs one executed verification; the merge card says "Reviewed in run mode". — "run mode: the reviewer ran …", "the merge card says 'Reviewed in run mode'".
3. Run mode with no test command, or a run the sandbox refuses: "not executed: <reason>" recorded and flagged on the merge card (needs your eye); the verdict stands, no loop. — "run mode with no test command …", "run mode, a run the sandbox refuses …".
4. Type-aware reads (src/review-read.ts) count as read: text (lockfiles too) by ranges; images as pictures through the vendor's image input (MCP image block, Anthropic image block; logs keep a note only); PDFs as page text (plain and Flate) and page 1 as a picture (macOS Quick Look); other binaries as type, size, sha256, hex head and the base version's metadata. Paths are normalised. — "an image is returned as a picture …", "a PDF is returned …", "an opaque binary is shown …", "a lockfile is read as text", "review-depth counts every view as read …", "an image read goes to the model as an image block …".
5. The read budget (`reviewer.read_budget`, default 40 reads): over it, the done lines' files plus a sample are required, the rest "not read: budget", carried in the verdict and on the merge card; a file over the read cap is "not readable" with its reason. — "over the read budget …", "the required files must be read …", "a file over the read cap is 'not readable' …".
6. A review still refused after its retry raises the step-back card (another model as provider/model, rescope, drop), never a failed run; "another model" runs the next review on it; drop parks the run. — "still shallow after its retry …", "'another model' runs …", "drop parks the run …".

r2 (the r1 REJECT, all seven items):
1. Run mode on a fresh checkout with nothing installed: the copy's dependencies come from the project's `install` policy (else bun install --frozen-lockfile), in the round sandbox, the network only to `egress.allow`; both run tools run on clones of that installed copy. — "run mode on a fresh checkout with no dependencies installed …", "the install reaches the network only …", "the project's install policy installs …".
2. A tool result's picture is its own part of the provider contract (`toolParts`): Anthropic maps it to an image block, OpenAI and OpenAI-compatible get the text with a note, the stub too; claude and codex get it through Studio's MCP server and their events keep a note. — one assertion per provider.
3. Untrusted files are read with caps and off the event loop: Flate output capped per stream and in total, a linear PDF scan (no backtracking pattern), Quick Look, git show and the copy as async helpers with timeouts, the listing and search bounded. — "a Flate bomb …", "a crafted PDF …", "a PDF read keeps the event loop free …".
4. Done lines 3 and 5 asserted on real built merge cards (body and detail). — "run mode, a refused run: the built merge card …", "over the read budget the built merge card …".
5. The editor's edge drop is a real pointer drag again; the cause is fixed in the router: a back edge's legs and arc keep off every forward edge's middle (graph-tidy "no back edge covers a forward edge's middle", every built-in workflow and view, plus r1's definition). code-firstmate's crossings: 14 (threshold back to 17).
6. run_command and run_tests resolve their program on a fixed PATH inside the copy; the sandbox never adds the program's folder to its reads (`argvRead: false`). — "run_command refuses …", "with argvRead: false …".
7. Done lines name paths on path boundaries; required reads stay within the budget (a named file over it is "not read: budget"); maxTools is sized from the plan. — "only src/a.tsx is named …", "the review's tool budget is sized from its plan …".
