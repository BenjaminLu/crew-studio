## Goal and human journey

Create a named coffee-shop workflow from a source-pinned built-in template,
connect a standalone available model account, enter the actual brief and
confirm a concise shared direction. The default view explains the steps and
next action; Advanced retains the existing full graph editor. No terminal
session selection, graph editing or coding-project enablement is required.
This domain owns only native artifact folders, never arbitrary Git paths.

Page drafting and image creation run independently under existing live-round
capacity. They consume the same signed brief/design token snapshot: warm
natural light, wood/cream palette, readable serif headlines, restrained motion,
spacing/type tokens and exact language/copy. The first real generated image is
already accepted by the captain as this example's visual direction. Importing
it for acceptance records import provenance; never manufacture a native agent
round or claim this Task generated an imported file.

Film composition waits for exact image/page generations, then the approved
HyperFrames adapter renders a real 10–15s MP4. Assemble a new versioned website
containing the actual image and playable video as local files. A site with only
links to separate files does not satisfy completion. No automatic publishing.

## Authority and persistence

Use normal Engine-owned nodes, signed ledger records, artifact versions,
captain cards and the existing queue. No generic runtime/domain policy mixing
or separate scheduler. Non-agent image/render jobs acquire/release actual live
round leases and use Engine abort/ownership callbacks. No async task can write
an artifact, a card or a completion record after cancellation/deletion.
Preflight uses the explicitly approved available provider/model, preserving
the selected effort. Ordinary provider safety flags remain unchanged.

Record an immutable direction pin before jobs. Each output receipt binds:
Task/node/visit, direction hash, generation, artifact/version and the FULL
ordered file manifest with path, size and SHA256. All input dependencies use
exact receipts, not current ctx/latest pointers or primary-file hashes only.
Records are accepted only from the fully trusted ledger. Unknown/old receipt
formats hold and offer explicit fresh preparation; no history rewriting.

## Refine loop

Offer useful actual page/image/video previews and clearly state whether the
Task awaits the captain, model work, a dependency or unavailable tools. A
preview card accepts a specific target plus a required concrete comment:

- page change: preserve image; rebuild affected page/film/site dependencies.
- image change: preserve unrelated page copy; create a new image version,
  invalidate dependent film/site, then render/assemble new versions.
- video change: preserve image/page source; revise composition and site only.
- shared direction change: confirm a new immutable direction generation and
  invalidate all affected outputs explicitly.

Never annotate both independent producers for a single-target request. Preserve
old versions and approval history. Limit automated repair/refine attempts to
three per requested revision; a stalled/error/capability condition presents
HOLD, step-back or cancel, not an endless retry or a false successful artifact.
Do not add a separate render approval click without a material new authority
or cost boundary; direction approval covers the bounded local encode.

## Final acceptance

The final card binds its own visit/id plus the complete current bundle receipt.
Display deterministic integrity/containment checks as proved and content,
image quality, video pacing and visual coherence as human judgment. On answer,
re-read/revalidate every file and dependency generation, exact receipt and
trusted ledger; reject stale cards and superseded dependencies without any
approval/Library/Done side effect. Only approve the whole integrated website
and its pinned image/film as one bundle. Alternative A/B selection is not a
bundle. A capability HOLD must never expose an approve action for absent video.
