# Native queue and vendor policy (C2/C3)

References: architecture §3.2/§10, code-firstmate-pipeline build/review/merge contracts; read-only gap audit C2/C3 rows 339–340; firstmate design §15.10 and pinned-scope overlap T-278/T-296; firstmate skill T-174 vendor policy. No v1 data projection, state import or sidecar launcher.

## Findings and capacity contract

Engine.start currently schedules immediately; Agents.run immediately starts every requested job. Waiting captain cards and completed worker rounds are different from live owned job capacity. Firstmate design §15.10 explicitly counts actual live owned rounds, fair-fills the project with fewest live rounds, ties by name; its engine config declares concurrency 3. The gap audit adds a per-project cap. Proposed native policy has an explicit documented global live-round cap of 3 and per-project cap of 3, each validated positive bounded integers and configurable through existing policy resolution. These are product policy values derived from the canonical config, not the harness's four slots. A waiting card consumes no live-round slot; its accepted immutable code scope remains reserved until an authoritative verified merge, independent of slot release. No admission process preempts live work.

Code dependencies require actual verified merge evidence bound to task/project/repo/base/head and trusted signed ledger, with current authoritative local ref/ancestry or grant-bound remote identity. A parked/cancelled/failed/closed-without-merge parent never counts as ready; succeeded alone and mutable ctx.merged alone never authorize. Unknown/deleted/corrupt parents hold/refuse truthfully. Remote merge remains unavailable in the current unit, so remote dependencies without supported authoritative evidence hold; no remote merge implementation is smuggled into C2.

Readiness and scope admission occur before the first worker executes against its accepted native spec; the pin includes dependency identities, project/repository and scope digest. Coordinator planning can run without claiming worker readiness. Overlap compares pinned scopes conservatively (literal/glob/static-prefix; tests excluded as canonical), reserves atomically against same-batch starts, and stays held through completed rounds and captain waits. An unresolved cancelled holder does not falsely become merged; explicit safe abandonment policy must distinguish untouched work from an existing unmerged branch. Existing historical tasks are not rewritten or given synthesized pins: an unbound in-flight worker request gets a capability/recovery card for fresh preparation rather than approval.

Non-code artifact workflows use ordinary bounded live-job capacity and their artifact/plan acceptance semantics; they are not forced to Git-merge. Code and local README lane merge evidence are only applicable to explicitly declared code dependencies. Queue state and owned reservations survive native task replay; interrupted jobs reclaim only after actual process ownership completes. Cancel removes only that task's queued request and owned wait. Completion/merge/cancel/policy edits wake the queue through existing owned runtime callbacks and microtasks; no OS poller, second coordinator or imported firstmate wake file. A bounded absolute readiness deadline persists across restart and reports a hold/capability outcome without fake green.

## Vendor contract

Worker default is opposite confirmed host (Claude → Codex; Codex → Claude), then host vendor, then explicitly configured fallback list. Explicit node/role/provider choice remains explicit, with its existing role model. An unknown host follows the configured fallback head with a recorded reason; missing chain cannot invent a provider. Reviewer remains its explicit role provider. Only a classified unavailable adapter, verified missing login or exhausted quota advances an authorized fallback chain; unverified auth and unknown quota hold without fallback; task/assertion/tool failure never falls through. Unknown provider IDs currently silently become Claude in makeProvider and server wrappers: fix that whole class to refuse.

Resolve each vendor's model from its own existing configured role/settings model; never reuse a Codex model for Claude or change captain gpt-6.1-sol/low or permissions. Unknown models are refused against the explicitly configured provider catalogue/capability probe, not sent to a CLI as a guess. Each launch requires fresh availability/auth/quota evidence from the native provider capability adapter. Doctor presence-only/unverified credentials and unknown quota cannot become green. Exhaustion raises a bilingual captain capability/recovery card; never silently selects an unknown model. No global config, CLI model/effort/sandbox permission override or installation.
