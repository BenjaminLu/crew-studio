# Live workflow overview

**Superseded (board round 6, docs/units/board.md):** the Board no longer draws a graph per workflow. It is a task overview: one row per Task, and a detail panel with one Task's visited path. public/workflow-overview.js is removed. The refresh contract below still holds for the rows: membership comes from the default list, stale details are rejected, navigation cleans up, a subscription recovers, and the shared notice keeps its clearance. Its tests (tests/workflow-overview-*.mjs) now check the rows.

The Board shows one read-only graph per workflow with unresolved **native Studio Tasks**. The captain authorized this view goal. The older T-308/T-310 projected fixture clauses are void: no import, projection or shadow Tasks participate. Scope: public/workflow-overview.js, public/board.js, public/board.css, public/index.html, public/runtime.js, this unit contract, tests/workflow-overview-ui.mjs, tests/workflow-overview-races.mjs and package.json.

Needs you remains first; recent ended Tasks and the existing Task rows remain available. Code-firstmate appears first. Geometry comes from the editor's crewLayout.layout and pathD, with additional vertical space for token stacks. Each token uses actual current running/waiting nodes, queued node IDs, or the explicit terminal failure event’s node/known blocked nodes; parallel frontiers appear simultaneously. No past node is inferred to be current, and infrastructure errors do not imply blocked. Paused and queued retain their truthful labels. Tasks without an authoritative frontier remain accessible in the equivalent list with an explicit no recorded current node explanation.

Tokens show Task ID, short title, state and a hover title. Stacks show the number of Tasks at that node and the oldest actual current wait timestamp. A captain-wait token links directly to its open native card for the same node and visit; every other token links to the canonical Task page and its Rounds. Failed Tasks remain unresolved until archived or removed. Archived, closed, cancelled and succeeded Tasks are excluded. The native default list is authoritative, so retained detail caches cannot resurrect archived/deleted Tasks.

The Board's existing SSE connection moves tokens after node/Round transitions and refreshes cards and archive/delete changes without reload. The graph owns its horizontal/vertical scroll frame; the page never acquires sideways scroll. One button switches to an equivalent keyboard-accessible list on every screen. Pinned definitions are used, not the current editable definition. If active Tasks use several versions of one workflow, the graph explicitly labels its combined pinned versions and unions their actual node and edge identities; tokens still derive from each Task's own frontier.

Acceptance evidence uses real native engine Tasks persisted into a real isolated server: two same-node waiting Tasks in code-firstmate, a second workflow with parallel waiting nodes, and an explicit failed Task. It verifies card identity, counts, oldest wait, canonical detail links, native exclusions, live moves after answering a Round, archive/unarchive/remove, graph/list parity and 1440/390 light/dark English/Traditional Chinese views. Captures include full graph/list, graph middle, real captain card, each live changed state and phone page end with firstmate visible. No service, model/vendor configuration or external write belongs to this unit. Capacity formatter consolidation is deferred.

R2 refresh contract: an accepted default list alone owns membership. Every native event invalidates per-Task detail generations and the in-flight list generation; queued refreshes survive an existing list request. Archive/delete immediately exclude the ID and cancel its timer/request. Unarchive (`archived:false`) requests authoritative membership without removing it. Node event sequence checks and latest-request identities reject older frontiers. Navigation cancels outstanding Board work, and returning reads a fresh default list. Card revisions separately prevent stale card snapshots from replacing newer decisions. Native card events refresh immediately; in-flight reads returning during a disconnected stream cannot clear known decisions, and reconnect requests current cards and a queued default list. Native IDs are immutable; creation starts a fresh ID, tested while an older list response is held.

Native card refresh uses the Board’s existing soft render while a captain field is focused. Direct live-card rendering could move its reused mounted card and trigger recursive blur redraws; unrelated updates must keep the note and focus. Closed-card pruning retains its existing explicit blur/removal behavior.

Initial subscription recovery: every actual stream hello on Board invalidates card reads and queues an authoritative default-list refresh, including while cards are still null and an initial read is held. A real unarchive before subscription must appear after hello; stale excluding initial snapshots cannot hide it. The regression delays actual subscription and drains pre-subscription queued reads before releasing the final stale snapshot.

R5 shared overlay clearance: the real native new-card notice sits above the full Firstmate launcher dock at desktop and phone widths, including safe-area spacing. With Firstmate open it sits below the drawer header, clear of its close control and composer. Live moved/archive/unarchive/remove captures cover 1440/390/320, light/dark and EN/zh-TW; browser checks use actual native new cards and actual Firstmate, Show and Dismiss clicks, not synthetic DOM. Scope includes public/runtime.css for the shared notice owner.

Race fixture observation contract: subscribe to the fresh-list response before the mutation. The archive POST body is deliberately delayed until the actual newer excluding list has arrived, proving list reconciliation can precede the POST response. Normal live-race cases require actual stream hello; the separate initial-subscription regression still deliberately mutates before subscription. Unarchive requires an actual native event, fresh authoritative inclusion and the rendered token, while stale-token exclusion assertions remain intact.

Subscribed creation and restoration races also establish actual Live/hello before mutation, install fresh-list observers first and require their real wrun receipt before releasing held reads. Creation must return in the fresh default list and render its token; cancelled restoration returns in default membership without becoming an active token. The independent delayed initial-subscription barrier remains unchanged. Read-only private debugger diagnostics are retained externally, not dependencies of the canonical suite.

Pre-armed creation/restoration response waits attach rejection handling immediately, then surface failures at their original await point with existing browser receipts and timestamped request/response/body/finished/failed and held-request identities. This changes failure reporting, not mutation order or production behavior. Response-body retrieval errors are retained rather than silently discarded; the journal is emitted at suite completion without a pre-mutation diagnostic await.
