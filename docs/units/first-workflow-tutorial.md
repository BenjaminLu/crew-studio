# First workflow authoring tutorial

Open Workflows → First workflow tutorial, or choose Build my first workflow in the first-use guide. The coffee shop stays available as the advanced example.

## What the captain does

1. **Interview (free).** Describe the goal (kept in this browser), then press Interview with Firstmate. The chat input is prefilled; nothing is sent until the captain sends it. Firstmate asks two or three short questions.
2. **Generated graph and live preview (free).** Firstmate calls the native tool `studio_draft_workflow` with the graph its model designed. The page picks the draft up live and shows the nodes, the edges and the graph JSON, labeled **Generated by Firstmate · AI model** (and **edited by you** once the captain changes a node). The local starter remains available and is labeled **Free starter · not AI generated**.
3. **Edit each node's model (free).** Clicking an agent node opens inline settings: provider (Codex or Claude), model, reasoning effort and role skill (a bundled Studio role skill). Each save is a new draft revision on the server. The same settings appear in the workflow editor's node panel.
4. **Save as my workflow (free).** Saving creates workflow v1 with an immutable origin (`firstmate-draft`, draft id and revision). Repeating the save, from the page or through `studio_save_workflow_draft`, returns the same workflow. A lost starter-creation response holds further creation to avoid duplicates.
5. **Confirm staffing at Run.** The editor's Run button (and Tasks → Start for these workflows) asks the server to start. The server answers with the staffing plan, one row per agent node, and starts nothing. The Task starts only after the captain confirms that exact plan. A node with no provider/model (or a Codex node with no effort) holds Run until it is chosen. A workflow with no agent node (the free starter) has nothing to staff and starts directly.

Compare/annotate/refine and saving as a reusable template are not built yet.

## Boundaries

- Drafting, inline edits and saving never create a Task, never write a staffing record and never call a paid engine. Pack genesis is not used. `studio_propose_work` is execution and is not used for drafting.
- A model draft may use agent nodes in `deliver` mode (format document or web), card nodes with up to four options, and terminal hook nodes. Hook actions, other agent modes, file-path skills, unknown providers and graphs that do not validate are refused.
- The Run gate is enforced at engine start (`authorizeStart`) as well as in the route, so no other path starts one of these workflows without the confirmed plan. Firstmate cannot start them through a proposal.
- A node's provider, model and effort are what the engine uses for that node; a node's role skill overrides the role's bundled skill.

## Validation

- `bun tests/first-workflow-draft.ts`: actual server with the offline Codex app-server fixture as the model (it answers the interview message by calling `studio_draft_workflow` with `tests/fixture/first-workflow-draft.json`). Covers tool registration, the model draft and its label, refusal of unsafe graphs, inline node edits that survive a restart, idempotent save, origin kept across editor versions, and the Run gate (incomplete, confirmation required, forged param, wrong hash, confirmed start of exactly one Task).
- `node tests/first-workflow-draft-ui.mjs`: the same in a real browser, from the prefilled message to the confirmed Run, at desktop and phone width.
- `node tests/first-workflow-tutorial-ui.mjs`: the free starter path.
