# Unit check-runtime: the v2 runtime backbone and the check runtime

What: Studio runs workflows itself. A workflow is a versioned graph of the five node kinds (agent, check, card, loop, hook); a run is a state machine whose snapshot is the fold of its events; checks run under one contract (docs/check-contract.md) with a signed evidence ledger.

Why: docs/architecture.md §3–§6 and docs/check-contract.md are binding; until now Studio only mirrored firstmate's v1 board.

Done when (each line is proved by a test in `tests/runtime.ts`, which does not exist on the base, so every line is red there):

1. Definitions: only the five node kinds; one entry (no incoming edge), at least one end (no outgoing edge); orphans, dead ends, a check node with no check, and an unknown check are refused. — "only the five node kinds…", "a node no path reaches is an orphan", "every node must reach an end", "a check node needs a check attached", "an unknown check is an error", "two entries are refused".
2. Versions: an edit becomes v(N+1) with a diff (nodes added, changed, moved; edges added, removed); the old version stays; an edit of a stale version and an edit with no change are refused; dragged positions persist per version without a new version. — "an edit becomes v2 with a diff…", "v1 stays as it was", "an edit of an old version is refused…", "saving with no change is refused", "dragged positions persist per version…", "a layout change is not a new version".
3. Check execution: a crash, bad JSON, an unknown verdict and a timeout are `error`, never `pass`; the exit-code adapter maps the exit code and parses `file:line` findings; natives speak the same JSON; evidence lands in `out/`. — "a crash is error…", "bad JSON on stdout is error", "an unknown verdict is error", "a check killed at timeout_s is error", "the exit-code adapter…", "the adapter passes on exit 0", "a native check…", "a check writes its evidence into out/".
4. Params: schema defaults → policy (org → project → workflow version → run) → the workflow's override; values are checked against the schema. — "params: the workflow version's policy override beats org", "params are checked against the schema…".
5. Sandbox: inputs read-only, writes only in `out/`, no network (macOS sandbox-exec; elsewhere the Doctor says it is missing). — "sandbox: inputs read-only, writes only in out/, no network".
6. Judged checks: a finding without a locator is dropped; without a quorum a judged check never blocks; a quorum runs independent judges. — "a judged finding without a locator is dropped…", "a quorum of 1 of 2 runs two independent judges".
7. Ledger: every entry is HMAC-signed with Studio's local key and chained; tampering is detected; the done-line map splits proved lines from "needs your eye". — "every ledger entry is signed and chained…", "a tampered ledger entry fails verification", "the done-line map…".
8. State machine: parallel out-edges, join: all, the snapshot equals the fold of the events, transitions are `{ts, run, node, from, to, cause}` and stream over SSE; pause, resume, cancel. — "two out-edges run both targets in parallel", "join: all…", "the snapshot is the fold of the events", "every node transition is {ts, run, node, from, to, cause}", "transitions stream over SSE", "pause:…", "resume:…", "cancel:…".
9. Recovery: replaying the events of a run killed mid-node keeps finished nodes and runs the interrupted one again. — "recovery replays the events…", "after a restart the finished node is not redone…".
10. Hot swap: a live agent node stops, `data/handoff/<run>/<node>.md` holds inputs, progress, open findings and state, and the new agent finishes the node. — "a swap stops the live node…", "the hand-off file is data/handoff/<run>/<node>.md…", "the step points at its hand-off".
11. Cards: intent sections in en and zh-TW; answered exactly once; a one-way merge needs the door confirmation; the answer is signed into the ledger; an open auth window answers listed kinds and records the grant. — "a card carries its intent sections…", "a one-way merge needs the explicit door confirmation", "a card is answered exactly once…", "the answer is signed into the ledger…", "inside an open auth window…".
12. Edge checks and hooks: a blocking check on an edge re-routes as fail; a failing hook is reported and never moves the run backward. — "a blocking check on an edge…", "a failing hook…".
